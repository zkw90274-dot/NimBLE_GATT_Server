# IMU —— BMI270 驱动与姿态解算

> 上级索引：[../CLAUDE.md](../CLAUDE.md)

## 1. 硬件与引脚

引脚定义的**唯一事实来源**是 `E:\xiangmu\ESP-Spot Lite\main\board_pins.h`。本工程把它落成 Kconfig 项（值一一对应，改的时候两边都要动）：

| board_pins.h | 值 | 本工程 Kconfig | 用途 |
|---|---|---|---|
| `PIN_I2C_SCL` | GPIO1 | `CONFIG_IMU_I2C_SCL_GPIO=1` | I2C 时钟 |
| `PIN_I2C_SDA` | GPIO2 | `CONFIG_IMU_I2C_SDA_GPIO=2` | I2C 数据 |
| `I2C_BUS_SPEED_HZ` | `100 * 1000` | `CONFIG_IMU_I2C_FREQ_HZ=100000` | 速率 |
| `PIN_IMU_INT` | GPIO5 | `CONFIG_IMU_INT_GPIO=5` | data-ready 中断 |
| `BMI270_I2C_ADDR` | `0x68` | 组件默认 `BMI270_I2C_ADDRESS` | 器件地址（ADO 接 GND） |

**为什么是 100 kHz**：原理图上 SCL/SDA **没有任何外部上拉电阻**，全靠模块自带；`board_pins.h` 记录了 ESP-Spot Lite 自检时"100 kHz + 内部上拉，稳妥优先"的结论。代码里 `sda_pullup_en` / `scl_pullup_en` 都使能了内部上拉。确认外部上拉存在后才可提到 400 kHz。

I2C 总线实例为 `I2C_NUM_0`，由 `espressif/i2c_bus` 组件创建（**硬件** I2C，不是软 I2C）。本工程只有 BMI270 挂在这条总线上，无总线共享问题。

## 2. 驱动路线

```
espressif/bmi270_sensor  ^0.1.0  (实际 0.1.2)
espressif/i2c_bus        ^1.5.0  (实际 1.5.2)
```

`bmi270_sensor` 内部打包了 Bosch 配置固件的**预编译二进制**，并自行完成 8 KB 上传时序 —— 所以本工程**不需要内嵌配置数组**。

**配置固件用的是 `bmi270_toy_config_file`（TOY 集）**。BMI270 同一时刻只能加载一份配置固件，组件里共提供三份（标准 / CIRCLE / TOY），9 个官方示例中 7 个走 TOY。选 TOY 的理由：够用（六轴数据 + 将来若要做 shake/tap/push 等特征都在这一集里），且与同类板级工程一致。

> ⚠️ 若将来要改用 **CIRCLE 集**（`bmi270_circle_config_file` + `bmi270_circle_*` API，可做 multi_tap / circle_gesture），**TOY 集的特征会全部失效**，因为它们不是同一份固件。两集的 API 前缀也不同，不能混用。

**不要** `#include <driver/i2c.h>` —— `i2c_bus.h` 会按 IDF 版本自己选驱动头，并自带一份 `i2c_config_t` 定义，手动引入旧头会冲突（`conflicting declaration 'typedef struct i2c_config_t i2c_config_t'`）。`driver/gpio.h` 无此问题，可以正常引入。

## 3. 量程、ODR 与换算

配置在 `imu_configure()`（`main/src/imu.c`）：

| 传感器 | ODR | 量程 | 其他 |
|---|---|---|---|
| 加速度计 | 200 Hz | ±4 g | `BMI2_ACC_NORMAL_AVG4`，`BMI2_PERF_OPT_MODE` |
| 陀螺仪 | 200 Hz | ±500 dps | `BMI2_GYR_NORMAL_MODE`，`BMI2_POWER_OPT_MODE` |

对应换算常数定义在 `main/include/imu.h`，**与量程强耦合，改量程必须同步改它们**：

```c
#define IMU_ACC_LSB_PER_G   (8192.0f)   /* 2^15 / 4    */
#define IMU_GYR_LSB_PER_DPS (65.536f)   /* 2^15 / 500  */
```

> `bmi2_set_adv_power_save(BMI2_DISABLE, ...)` 是**必需**的：开着高级省电会停掉采样通路，典型症状是"寄存器读写全部正常，但三轴恒为 0"。

## 4. 姿态解算

### 4.1 姿态滤波器

**只有一套：Fusion AHRS。** 状态是四元数，欧拉角只在最后一步转换。

2026-09-23 曾并行跑过第二套（kaerman 工程移植的 Mahony）做同批采样 A/B，
**Mahony 在所有静止指标上都输、晃动指标上打平**，已移除。完整对比见 §4.9，
被否的方案与其教训留档在 §4.3。

### 4.2 Fusion —— xioTechnologies AHRS（vendored）

`main/fusion/`，逐字节 vendored，来源与许可见 `main/fusion/README.md`。
用的是 `FusionAhrsUpdateNoMagnetometer()`：本板无磁力计，航向不可观测。

- 状态是四元数，积分与归一化都在四元数上（`FusionAhrs.c:167-169`），**欧拉角只在最后一步转换**
- 约定 `FusionConventionNwu`；加速度计在静止读 `(0, 0, +1 g)`，与 `imu_read()` 的原始值一致

**`IMU_AHRS_GAIN = 0.2`**：Fusion 的倾斜时间常数是 **1/gain 秒**，与采样率无关。
库里默认 0.5，第一轮动态测试在静止 20 s 里看到约 ±0.8°、周期约 10 s 的 pitch 摆动
（环路过于相信加速度计的典型征兆），降到 0.2 换更安静的静止角。

**实测**（2026-09-23，宿主端用同一批源文件、同 200 Hz、5° 加速度计阶跃）：
gain=0.2 在 **5.0 s** 走到阶跃的 63%，即恰好 1/gain。

### 4.3 被否的备选：Mahony（kaerman 工程，已移除）

留档在这里，因为里面几条结论**属于 kaerman 工程本身**，将来回去用它还会踩到。

**① kaerman 的数学库在高角度误差严重。** 它的 `imu_math.c` 用泰勒级数自己实现
三角函数，实测截断误差：

| 角度 | `imu_safe_asin` 误差 | `imu_safe_atan2` 误差 |
|---|---|---|
| 30° | -0.000° | -0.000° |
| 45° | -0.008° | **-1.784°** |
| 60° | -0.256° | +0.000° |
| 75° | **-2.647°** | +0.000° |
| **84°** | **-7.194°** | +0.000° |
| 89° | **-11.309°** | +0.000° |

`asin` 正是 **pitch** 的算法，而本项目 pitch 到过 84.49° —— 照抄会差 7 度。
移植时把标量数学换成了 libm（接口名与算法结构一字未动），**上游的问题仍在**。

**② 误差积分没有乘 `dt`。** `ahrs.c` 里是 `s_ex_int += ex * AHRS_KI * weight;`，
积分增益因此**与采样率绑定**。kaerman 与本项目都跑 200 Hz，这次移植不受影响；
**改采样率必须重新标定 `AHRS_KI`**。

**③ 欧拉角反解公式两套完全一致**（ZYX 顺序，`atan2`/`asin` 三个分量逐项相同），
所以 A/B 的差异只能来自滤波器本身、不可能来自反解 —— 实测也确认了没有符号翻转。

**④ Kp 必须按倾斜时间常数定标，不能照抄。** kaerman 原值 `AHRS_KP = 8.0` 是按
ICM-42688-P 调的，实测在本项目 200 Hz 下时间常数只有 **0.125 s**，比已调好的
Fusion（5.0 s）快 **40 倍** —— 那不是滤波而是直接跟加速度计走。移植时取
**`AHRS_KP = 0.2`**、`AHRS_KI = 0.00005`（同比例缩 40 倍以保持控制器形状）。

**⑤ 它为什么输 —— 结构性原因。** Mahony 的误差积分项是 `e = acc × gravity`，
叉积结果**垂直于重力、没有沿重力轴的分量**。绕重力轴旋转不改变加速度计读数，
所以它**原理上无法估计 yaw 轴零偏**：开机那 0.32 s 一次性标定留下的残差
（实测约 0.2 dps）没人修正。这是算法结构的缺口，不是调参能补的。

### 4.4 陀螺仪过载重启 —— 已关闭的坑 ⚠️

**Fusion 自己的过载检测现在是关的**（`imu.c` 里 `gyroscopeRange = 0.0f`）。

给它 `IMU_GYRO_RANGE_DPS` 会把阈值设成 `0.98 × 500 = 490 dps`。任何一轴超过这个值，
Fusion 就调 `SoftRestart()` —— 而它接下来 3 秒（`STARTUP_PERIOD`）里做两件坏事
（`FusionAhrs.c:20-25`、`:243`）：

1. 增益从调好的 **0.2 跳到 `INITIAL_STARTUP_GAIN = 10.0`**，50 倍；
2. `HalfInclinationFeedback()` **完全不再看 `accelerationRejection`**，加速度计无条件采信。

而手抖幅度轻易打满这个 ±500 dps 量程 —— 触发时机恰恰是加速度计最不可信的时候。

**实测**（宿主端，一个 550 dps 采样，随后加速度计谎报 30° roll 误差，拒绝阈值 10°）：

| `gyroscopeRange` | roll 结果 |
|---|---|
| 500（检测开） | **+30.000** —— 谎报被完全采信 |
| 0（检测关） | **+0.000** —— 谎报被丢弃 |

那个采样**不是坏数据**（陀螺仪真的读到 550 dps，只是量程到头了），
所以 §4.5 的合理性闸门也拦不住它 —— 闸门只拦"物理上不可能"的值。

**代价**：关掉之后过载时滤波器继续积分而不重启。饱和样本（被削到 500）仍会被积分，
这段旋转仍然少算 —— 但那是量程的物理限制，**关掉过载检测并不让它更糟**，
丢掉的是"重启后 3 秒的高增益"。

**真机旁证**（2026-09-23，见 §4.9）：关闭后晃动阶段 `roll std` 从上一轮的 46.75 降到
**34.01**，而同时段纯加速度计基准从 92.22 **升到** 102.10（说明这次晃得更猛）。
在"晃得更猛却输出更稳"的方向上变化，与关掉过载重启一致。
**但两次晃动是两只手，不能当作严格对照** —— 要证实得在同一批采样上开关对比。

> **更彻底的做法**：高动态阶段把陀螺仪切到 ±1000 dps 量程，抬高削顶点而不是绕过它。
> 代价是 LSB 分辨率减半，需要单独的动态测试才能采纳，目前**未做**。

### 4.5 yaw —— 相对角，会漂移 ⚠️

**BMI270 是 6 轴无磁力计器件，航向角在原理上不可观测**（没有地磁或其它外部参考）。
参考工程因此**根本没有输出 yaw**。

本工程按需求补上了 yaw，但它的性质必须清楚：

```
yaw = ∫ (gyr_z - bias) dt        开机时归零，bias 为开机静置标定值
```

- **滤波器不对 yaw 做任何校正** —— 绕重力轴旋转不改变加速度计读数，
  所以 yaw 在加速度计里根本不可观测，反馈项里也**没有** yaw 分量
- 这是**相对转角**，不是绝对方位。秒级到分钟级可用，会缓慢漂移
- **不要**用在需要绝对方位的场合（罗盘航向、绝对朝向）
- 要绝对 yaw 必须加磁力计（BMM150 / QMC5883 等），那是另一件事

积分步长做了保护：`dt` 为 0（首次调用）或 `> 0.5 s`（长时间停顿，如调试器 halt、任务被阻塞）时**跳过本次积分**，避免把一大段时间一次性乘进去造成跳变。结果回卷到 `-180°..+180°`。

### 4.6 零偏标定

`imu_calibrate_gyro_bias()`：开机后取 **64 个样本、每 5 ms 一个（约 0.32 s）** 求平均，得到陀螺仪 Z 轴零速率偏置。

**必要性**：BMI270 数据手册的零速率偏置在 ±1 dps 量级，而 yaw 是积分量，残留偏置会**线性累积** —— 不标定就是约 **60°/分钟** 的漂移。

标定值超过 `IMU_GYRO_BIAS_WARN_DPS = 5.0` 会打 WARN，提示"开机时板子可能在动"。**因此开机后约 0.5 s 内板子必须静止**，否则 yaw 基准是错的。

这个标定值会从送进滤波器的角速度里减掉。除此之外 `FusionBias` **持续**跟踪三轴残差
（覆盖一次性标定覆盖不了的温漂），两者相加而不是互相打架。

**`FusionBias` 不是可选项。** 0.32 s 的一次性标定留下约 **0.2 dps** 残差，而 yaw 是积分量 ——
那就是 **12°/分钟**。2026-09-23 那套没有等价估计器的 Mahony 实测漂的就是这个数（§4.9）。

### 4.7 合理性闸门

`imu_read_attitude()` 把样本送进滤波器之前先验一次：

| 条件 | 阈值 | 判据性质 |
|---|---|---|
| 加速度模长 | `0.1 g .. 7.0 g` | "物理上不可能" |
| 各轴角速度 | `<= IMU_GYR_MAX_DPS = 510` | 超出量程即不可能 |

**阈值必须设在"物理上不可能"而不是"不寻常"。** 第一版用了 ±2 g 窗口，
晃动阶段丢掉了 **25%** 的样本（手持晃动能到 3.34 g，还会路过近自由落体）——
**恰好在最需要滤波的时候把滤波器饿死了**。放宽后第二轮测试 1600 个采样只丢 1 个。

被闸门丢掉的样本**不推进滤波器**（上一帧姿态原样重发，数据流不中断），
但计数会累加，动态测试总结里的 `gate N rejected sample(s)` 就是它。

### 4.8 动态精度测试

`CONFIG_IMU_DYNAMIC_TEST`（`main/src/imu_dyntest.c`）。8 个引导动作，全部由串口提示驱动，
操作者按倒数执行，日志自带标签、不需要事后对时间戳。

每个阶段对**同一批采样**统计两路角度，总结里给出对照表：

```
=========== 滤波 vs 不滤波（同一批采样，std 越低越好）===========
                       fused accel-only
shake  roll std       34.009    102.095
shake  pitch std      14.512     46.836
quiet  roll std        0.026      0.085
quiet  pitch std       0.031      0.081
quiet  yaw std         0.010        n/a
```

（上面是 2026-09-23 的真实输出，§4.9 那次 A/B 运行。）

- `shake` 行 = **抗线性加速度能力**，纯加速度计那列就是要被滤掉的东西
- `quiet` 行 = **静止抖动**，改环路增益时看的就是它
- 两个纯静止阶段（首、尾）是静止抖动的基准
- 每阶段还有一行 `fusion/fused … | accel …` 的实时轨迹，每 200 ms 一条

**测试期间 IMU 任务和心跳任务的周期日志被静音**（`imu_dyntest_is_running()`），
倒数步长 1.5 s、动作前留 2.5 s 读提示 —— 一秒的倒数看不清，提示会被自己的日志冲掉。

### 4.9 为什么只有 Fusion —— 2026-09-23 的 A/B 实测（留档）

> 这是**决策依据**，不是当前行为：Mahony 已按结论移除（§4.3）。
> 重跑这套对比需要把那两套并行跑的代码加回来。

同一批采样，一次运行，三路对照：

| 指标 | Fusion | Mahony | 纯加速度计 | 判读 |
|---|---|---|---|---|
| shake roll std | **34.009** | 34.311 | 102.095 | 两套都压掉约 3 倍；**两者打平** |
| shake pitch std | **14.512** | 15.239 | 46.836 | 同上 |
| quiet roll std | **0.026** | 0.094 | 0.085 | **Fusion 好 3.6 倍**；Mahony 连不滤波都不如 |
| quiet pitch std | **0.031** | 0.055 | 0.081 | Fusion 好 1.8 倍 |
| quiet yaw std | **0.010** | 1.163 | n/a | **Fusion 好 116 倍** |
| quiet 极差 (roll/pitch/yaw) | 0.110 / 0.149 / 0.037 | — | — | 20 s 静止窗 |

**Mahony 的 yaw 在漂，而且是线性漂**：20 s 的静止尾窗里 yaw 从 +4.93 单调爬到
+8.93，**+4.00° / 20 s = 12°/分钟**。同一窗口 Fusion 的 yaw 极差只有 **0.037°**。
原因见 §4.3 ⑤。

**这算不算对 Mahony 不公平？** yaw 那一项算 —— 它缺的是 `FusionBias`，
一个**独立的**偏置估计器，不是滤波器本身。但 **roll/pitch 的 3.6 倍差距不是**：
两套的倾斜时间常数都是 5 s、都有加速度计校正，差别出在 Mahony 积分项在静止时的游走。

**即使给 Mahony 补上偏置估计、把 Ki 关掉，它最好的结果是追平 Fusion**，
代价是重建一个 Fusion 已经有的东西 —— 没有收益。所以移除。

### 4.10 `roll~90` 那步暴露的万向节锁

第二轮（`roll~90`）的实测里，**pitch 被钉在 +90.00 整整 2.5 秒**，同时 roll 从
-164.90 甩到 -67.18。逐行看 `roll - yaw`：

```
fusion -164.90  +87.86 -160.50     roll-yaw = -4.40
fusion -136.19  +90.00 -132.82     roll-yaw = -3.37
fusion -142.17  +90.00 -138.67     roll-yaw = -3.50
fusion  -67.18  +90.00  -64.63     roll-yaw = -2.55
```

`roll - yaw` 基本恒定 —— 这是 **ZYX 欧拉角在 pitch = ±90° 处退化**的特征：
此时 roll 和 yaw 各自都没有意义，只有它们的差是确定的。

**这条对做 3D 显示的上位机是硬约束**：不要用欧拉角驱动万向节式的 3D 姿态显示，
**用四元数**。滤波器内部状态就是四元数，但 BLE 报文里只有欧拉角 ——
真要用，得加一条四元数特征，那是另一个需求。

**注意**：这**不是**上一轮那个"yaw 卡在 ±0.00 约 4 秒"现象的解释 ——
那次 pitch 只在 ±30~48°，没到退化点。那次的现象在本次（关掉过载重启之后）
**没有复现**，与"过载重启是元凶"一致，但只有一次数据，**不算证实**。

## 5. 采样与上报架构

```
BMI270 (200 Hz ODR)
   │  INT1 脉冲
   ▼
GPIO5 上升沿 ──► ISR（只做一件事：vTaskNotifyGiveFromISR）
   │
   ▼
IMU 任务 ──► imu_read_attitude()  ← 每个 data-ready 采样一次，yaw 积分跑在 200 Hz
   │
   ├──► ESP_LOGI（每 IMU_LOG_DIVIDER 包一条；打出来的仍是真正发出去的包）
   └──► send_imu_notification()   ← 交给协议栈，实际速率由连接间隔决定
```

**为什么采样和上报要解耦**：传感器出数 200 Hz，BLE 承载不了；但 yaw 是积分量，采样越快积分越紧。所以取样的节拍跟着传感器，radio 的节拍单独控制。

### 5.1 上报速率由谁决定

三层，越往下越硬：

| 层 | 位置 | 当前值 | 作用 |
|---|---|---|---|
| 采样节拍 | `imu_configure()` 的 ODR | 200 Hz | 取数频率，决定 yaw 积分精度 |
| 限速器 | `CONFIG_IMU_NOTIFY_PERIOD_MS` | 10 ms | **只是"最早何时可发"**，不等于实际速率 |
| **连接间隔** | `gap.c` 的 `ble_gap_upd_params` | 请求 15–30 ms | **真正的上限** —— 通知只能在连接事件上发出 |

⚠️ **只调 `CONFIG_IMU_NOTIFY_PERIOD_MS` 而不动连接参数是无效的。** 把限速设到 10 ms（目标 100 Hz）后，实际速率仍被连接间隔压住（实测值见 [host-integration.md](host-integration.md) §8）—— 因为链路跟不上时，协议栈会**反压** `ble_gatts_notify()`，而不是丢弃数据。

**这意味着零丢包，代价是速率上不去时表现为"慢"而不是"空洞"**，对上位机是好事。

连接间隔的最终值由**主机**裁定，设备只能请求；具体代码与 `latency` 为什么必须是 0，见 [ble-interface.md](ble-interface.md) §4。

**中断配置**：`BMI2_DRDY_INT` 映射到 `BMI2_INT1`，电气属性为**推挽 / 高有效 / 非锁存**（非锁存 = 每个样本一个脉冲，而不是需要读状态寄存器去清的电平）。因此 GPIO 侧配的是 `GPIO_INTR_POSEDGE` —— **这两处必须一致，否则收不到中断**。

**ISR 里不做任何事**：不碰 I2C、不打日志、不调任何可能阻塞的 API，只发一个任务通知。

**降级设计**：任务用 `ulTaskNotifyTake(pdTRUE, pdMS_TO_TICKS(CONFIG_IMU_NOTIFY_PERIOD_MS))` 等待，**带超时**。所以中断不可用（GPIO 配错、线路断、`imu_start_data_ready()` 失败）时，采样不会停死，只是掉到 `CONFIG_IMU_NOTIFY_PERIOD_MS` 一次（当前 10 ms）。

## 6. 怎么验证它真的在工作

普通"能出数"不足以说明问题，因为**中断断线时的外部表现和正常时一模一样**（超时兜底照样出数）。所以 `imu.c` 里有一个 ISR 计数器：

```c
uint32_t imu_get_data_ready_count(void);
```

`main.c` 在武装中断后等 1 秒打印一次：

```
I (2173) imu: sampling paced by data-ready, INT1 on GPIO5
I (3183) imu: 203 data-ready interrupts in the first second
```

**203 ≈ 配置的 200 Hz ODR**，即中断确实在触发。以后改中断相关代码，**必须重新看这一行**。

真机实测参考值（2026-09-22，静止平放）：

| 量 | 值 |
|---|---|
| 零偏标定 | 0.041 dps |
| roll | ≈ -1.0°（噪声 ±0.12°） |
| pitch | ≈ -2.8°（噪声 ±0.13°） |
| yaw | ≈ 0.00°（静止 2 s 内无可见漂移） |
| 上报间隔 | 50/60 ms 交替（限速器对齐 5 ms 就绪网格的必然结果） |

## 7. 接口与文件

| 文件 | 职责 |
|---|---|
| `main/include/imu.h` | 对外接口：`imu_init` / `imu_start_data_ready` / `imu_read` / `imu_read_attitude` / `imu_get_latest_attitude` / `imu_get_latest_sample` / `imu_get_data_ready_count` / `imu_get_discarded_sample_count`，以及 `imu_sample_t`、`imu_attitude_t` 与换算常数 |
| `main/src/imu.c` | I2C 建立、BMI270 上电、量程配置、零偏标定、DRDY 中断、合理性闸门、姿态滤波器 |
| `main/fusion/` | vendored Fusion AHRS（见 `main/fusion/README.md`） |
| `main/src/imu_dyntest.c` | 引导式动态精度测试，由 `CONFIG_IMU_DYNAMIC_TEST` 打开 |
| `main/main.c` | `imu_task`：等中断 → 采样 → 限速上报 |

**线程安全**：`imu_read_attitude()` 在 IMU 任务里写缓存，GATT 读回调在 NimBLE 任务里读缓存，12 字节结构体赋值非原子，用 `portMUX_TYPE` 自旋锁保护。
滤波器内部状态（`s_ahrs` / `s_bias`）只被 IMU 任务碰，无需加锁。

**GATT 读回调返回的是缓存值**而非现场读取 —— 这样"日志里看到的"和"通知发出去的"是同一个数。

## 8. 已知限制

- yaw 非绝对（见 §4.5），无磁力计无法解决
- 开机后 ~0.5 s 需保持静止，否则零偏标定有偏
- 陀螺仪 ±500 dps 在剧烈晃动时会削顶，那段旋转量必然少算（见 §4.4）
- **pitch 接近 ±90° 时欧拉角退化**，roll 和 yaw 失去独立意义（见 §4.10）——
  上位机做 3D 显示要用四元数，而当前报文里没有
- 目前只输出姿态角；若要 shake / tap / push 等手势特征，TOY 集里有对应 API（`bmi270_enable_toy_*`），但**需要重新确认 INT1 映射**（特征中断与 data-ready 共用 INT1，`INT1_MAP_FEAT` 与 `INT1_MAP_DATA` 是不同寄存器）
